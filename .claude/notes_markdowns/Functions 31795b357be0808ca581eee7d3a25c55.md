# 1️⃣ What Happens When Function Is Called?

### Mental Model:

- Function call → **new stack frame**
- New local namespace created
- Arguments are **bound to parameter names**
- Execution happens inside frame
- Return → frame destroyed

Each call = new frame.

Recursive call = multiple frames stacked.

---

# 2️⃣ Argument Passing Model (Very Important)

Python is:

> **Pass-by-object-reference** (a.k.a pass-by-assignment)
> 

Meaning:

- Reference is copied
- Both variables point to same object
- Rebinding inside function does NOT affect caller
- Mutation DOES affect caller

---

## 🔥 Mutation vs Rebinding

### Rebinding

```python
def f(x):
	x = x+[1]
```

- New object created
- Local variable re-pointed
- Original untouched

---

### Mutation

```
deff(x):
x.append(1)
```

- Same object modified
- All references see change

# 3️⃣ `+` vs `+=`

For lists:

- `+` → new object
- `+=` → in-place (calls `__iadd__`)

For tuples:

- `+=` → new object (fallback to `__add__`)

So `+=` behavior depends on object implementation.

Never assume.

---

# 4️⃣ Default Arguments — Danger Zone

```python
def f(a,b=[]):
	b.append(a)
	return b
```

Default evaluated **once at definition time**.

Same object reused across calls.

Fix:

```python
def f(a,b=None):
	if b is None:
		b= []
```

Production rule:

Never use mutable defaults.

# 5️⃣ Full Parameter Types (Complete Order)

Correct order:

```python
(positional-only)      /
(positional-or-keyword)
*args
(keyword-only)
**kwargs
```

---

## Example of Maximum Signature

```python
def f(a, b, /, c, d=5, *args ,e ,f=10 ,**kwargs):
	pass
```

Meaning:

- `a, b` → positional-only
- `c, d` → positional or keyword
- `args` → extra positional (tuple)
- `e, f` → keyword-only
- `*kwargs` → extra keyword (dict)

---

# 6️⃣ `/` — Positional-Only Marker

```python
def f(a, b, /, c):
```

- `a, b` must be positional
- Cannot pass as `a=1`

Used in builtins like `len()`.

---

# 7️⃣  — Keyword-Only Marker

```python
def f(a, *, b):
```

- `b` must be passed as keyword
- Cannot pass positionally

Used for safe API design.

---

# 8️⃣ `args` and `*kwargs`

```python
def f(*args):
```

- args = tuple

```python
def f(**kwargs):
```

- kwargs = dict

---

# 9️⃣ Argument Binding Algorithm

When calling function:

1. Assign positional arguments
2. Assign keyword arguments
3. Fill defaults
4. Pack remaining into *args
5. Pack remaining keyword into **kwargs

Errors if:

- Duplicate assignment
- Missing required
- Unexpected keyword
- Too many positional

---

# 🔟 Common TypeErrors and Why

### Duplicate assignment

```python
f(1, a=2)
```

Parameter already filled.

---

### Unexpected keyword

```python
f(1, d=5)
```

Parameter doesn’t exist.

---

### Positional after keyword

```python
f(a=1, 2)
```

Syntax error.

---

### Passing positional to keyword-only

```python
def f(a, *, b):
	pass

f(1,2) # error
```

# 1️⃣1️⃣ API Design Lessons

Good backend functions:

- Keep required parameters positional
- Keep configuration flags keyword-only
- Avoid mutable defaults
- Avoid blindly accepting **kwargs
- Be explicit

# 1️⃣2️⃣ Mental Debug Checklist

When confused about function behavior:

Ask:

1. Was object mutated or rebound?
2. Is default argument reused?
3. Is argument positional-only?
4. Is argument keyword-only?
5. Is `+=` mutating or creating new object?

If you answer these 5, 90% bugs solved.

# 1️⃣3️⃣ Production Pitfalls

- Mutable defaults corrupt shared state
- Reusing global mutable objects leaks data
- Misusing `+=` creates hidden mutation
- Bad function signatures create silent bugs
- Blind `*kwargs` hides errors
