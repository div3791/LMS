# Python Decorators

---

# 1️⃣ Core Idea (One Line)

**Decorator = function ko wrap karke uska behavior change karna without modifying original code.**

Visual:

```
original function
      ↓
decorator wrapper
      ↓
extra behavior added
```

Example:

```
logging
authentication
rate limiting
caching
validation
```

These are called **cross-cutting concerns**.

---

# 2️⃣ Real Backend Problem (Why Decorators Exist)

Imagine backend APIs:

```
get_user()
create_order()
update_profile()
delete_account()
```

Each API needs:

```
authentication
logging
rate limit
metrics
```

Bad solution:

```python
def get_user():
		authenticate()
		log_start()
		# actual logic
		log_end()
```

Problems:

| Problem | Why bad |
| --- | --- |
| code duplication | repeated everywhere |
| messy functions | business logic mixed with infra |
| easy to forget checks | security risk |

Better solution:

```
decorate the function
```

# 4️⃣ What Python Actually Does

Code:

```python
@log
def process():
		pass
```

Python converts to:

```python
process = log(process)
```

Table:

| Step | What happens |
| --- | --- |
| decorator sees function | log(process) |
| decorator returns wrapper | wrapper |
| function replaced | process → wrapper |

So calling:

```
process()
```

actually calls:

```
wrapper()
```

# 5️⃣ Wrapper Structure

Typical decorator:

```python
def deco(func):

		def wrapper(*args,**kwargs):

		# before
		result=func(*args,**kwargs)

		# after
		return result

return wrapper
```

Flow:

```
wrapper start
↓
original function
↓
wrapper end
```

---

# 6️⃣ Execution Phases (Very Important)

Decorators have **two phases**.

| Phase | When | What runs |
| --- | --- | --- |
| decoration | file load / import | decorator |
| execution | function call | wrapper |

Example:

```python
@deco
def f():
```

Python runs immediately:

```python
f = deco(f)
```

Decorator executes **once**.

Wrapper executes **every call**.

# 7️⃣ Why `args` and `*kwargs`

Problem:

Decorator doesn't know function signature.

Examples:

```python
add(a,b)
get_user(id)
predict(data)
upload(file, meta)
```

Solution:

```
*args → positional args
**kwargs → keyword args
```

Universal adapter.

# 8️⃣ The Return Value Trap

Common beginner mistake.

Wrong:

```python
def wrapper(*args,**kwargs):
		func(*args,**kwargs)
```

Return value lost.

Correct:

```python
result = func(*args,**kwargs)
return result
```

# 9️⃣ Parameterized Decorators

Example:

```python
@retry(3)
@cache(ttl=60)
@rate_limit(100)
```

Requires **3 layers**.

Structure:

```
config layer
↓
decorator layer
↓
wrapper layer
```

Example:

```python
def retry(n):

		def decorator(func):

				def wrapper(*args,**kwargs):
						for _ in range(n):
								return func(*args,**kwargs)

						return wrapper

				return decorator
```

Transformation:

```python
@retry(3)
def fetch()
```

becomes

```python
fetch = retry(3)(fetch)
```

# 11️⃣ Why Function Runs Only Once

Your confusion earlier.

Each wrapper calls:

```
func()
```

But `func` is **next wrapper**, not always original function.

Example chain:

```
A wrapper
↓
B wrapper
↓
C wrapper
↓
original
```

So:

```
A calls B
B calls C
C calls original
```

Original function runs **once**.

# 12️⃣ `functools.wraps`

Problem:

Decorator replaces metadata.

Without wraps:

```python
func.__name__ → wrapper
```

Frameworks break.

Solution:

```python
from functools import wraps

@wraps(func)
def wrapper():
```

Copies:

Metadata

---

name

---

docstring

---

annotations

---

module

---

Important for:

```
FastAPI
Flask
debugging
introspection
```

# 13️⃣ Your Doubt Scenario (Important)

Your doubt:

> `f = A(B(C(f)))` me () hai → function call ho raha hai?
> 

Correct.

But these calls **build wrappers**, not execute original function.

Example:

```python
C(f) → returns C_wrapper
B(C_wrapper) → returns B_wrapper
A(B_wrapper) → returns A_wrapper
```

Final:

```
f → A_wrapper
```

Original function still inside.

# 15️⃣ When NOT to Use Decorators

Bad use cases:

| Case | Why |
| --- | --- |
| business logic | hides important behavior |
| complex control flow | hard to debug |
| heavy state management | better in class |

Decorators should handle:

```
infra concerns
```

Not:

```
business rules
```

Execution chain:

```

↓
outer decorator
↓

↓
original function
```

They are basically **middleware for functions**.

Exactly like:

```
HTTP middleware
```

in backend systems.
